# L - the tools, by group

L-1 to L-10 and L-3b are done and removed (docs/Plan.md, "Done, their
cards removed"). L-11 is below; L-12 and after are in
`docs/plan/L-tools-2.md`.

Every kind of tool that finds a fault the others miss, in groups, each with
what the project runs today and what it adds. The rule: a tool joins when it
is free and finds what nothing else here finds; it never replaces one that
works (formatting churn is the cost of a swap, not of an addition). Paid
tools are listed as wished for, not planned: they may never be used.

Where a tool runs: `CI` (a job or step in `.github/workflows`), `verify`
(`scripts/verify.cmake`, a preset or an `EXTRA` step), `planned` (a card
or milestone names it), `new` (a card below).

## L-11 - Mutation testing with Mull: the score of every component beside coverage, held above a floor

* **id**: L-11
* **goal**: `verify -DEXTRA=mutation` and a CI workflow `mutation` build the libraries with Mull 0.39.1's plugin (LLVM 21), run every unit test under `mull-runner-21`, and print, per component of `lib/`, the share of mutants a test kills; a component below its floor in `.mutation-floors.txt` fails the step.
* **why**: coverage (`EXTRA=coverage`, 89% of lines) says a line ran, not that a wrong line fails a test. The Roadmap's "Tests that are known to catch" (Suggestions of 2026-11-17) and "Next after 1.8.0" item 5 ask for mutation testing on the core and the readers, its score beside coverage; group 9 above plans Mull; 1.9.0's row in `docs/Maintaining.md` ("Versions") holds it; and the number is evidence `docs/Compliance.md` can cite.
* **needs**: nothing
* **size**: medium
* **decided**:
  * **Measured before the card** (2026-11-26, WSL `configforge-dev`, Ubuntu 26.04.1, 12 cores, the tree at 2395d65): the plugin build takes 67 s and is clean; 97 unit tests ran under `mull-runner-21` into one SQLite report in 72 minutes; 6,896 distinct mutants in `lib/*/src`, 95.1% killed. Per component, killed of all: base 92/96 (95.8%), config 3,211/3,348 (95.9%), lanes 91/114 (79.8%), numeric 423/446 (94.8%), platform 99/100 (99.0%), port 73/73 (100%), serialize 2,204/2,345 (94.0%), text 364/374 (97.3%). The slowest tests under Mull (seconds): `test_roundtrip` 1126, `test_predict` 560, `test_serialize` 552, `test_toml` 381, `test_live` 288, `test_emit` 163, `test_threads` 147, `test_oom` 127, `test_budget` 118, `test_codec_edges` 108, `test_text_space` 105, `test_yaml` 97; every other under 90. That run used Mull's default mutators (its `mull.yml` was not found from the build directory), so these are the numbers of `cxx_default`.
  * **The tool.** Mull 0.39.1, two packages of its GitHub release, each checked by SHA-256 before it is installed: `Mull-0.39.1-ubuntu-amd64-26.04.deb` (`809546a5d76c11fa5bcd70a3abdbe74e87dacf15ef8573b9274e40701596c0a2`; the tools, package `mull`) and `Mull-21-0.39.1-LLVM-21.1.8-ubuntu-amd64-26.04.deb` (`b8725bf3620b2a0b6f53ab249398cf0d61e3852dbd5941e0681a80b8f5fa9307`; package `mull-21`: `/usr/bin/mull-runner-21`, `/usr/bin/mull-reporter-21`, `/usr/lib/mull-ir-frontend-21`; it depends on `libllvm21`, `libclang-cpp21` and `mull (= 0.39.1)`). LLVM 21 because Ubuntu 26.04's clang is 21.1.8, on CI's `ubuntu-26.04` runners and in `configforge-dev` alike; the LLVM 22 package would need a clang neither has. Installed with `apt-get install -y --no-install-recommends ./<both .deb>`, which takes the LLVM libraries from Ubuntu's own archive. Mull's licence is Apache-2.0.
  * **The mutators**: `cxx_default` (increment, arithmetic, comparison, boundary), the set measured. `cxx_all` is not taken: it adds bitwise, assignment and call removal, more mutants on a run that already takes hours on CI. The configuration is `scripts/check/mull.yml`, given to the plugin, the runner and the reporter by the environment variable `MULL_CONFIG` (never found by walking up from a directory: the spike's was not). Its whole text: `mutators:` with the one item `- cxx_default`, then `includePaths:` with the one item `- '.*/lib/[^/]+/src/.*'`.
  * **The build**: a configure preset `mutation` in `CMakePresets.json`, after `coverage`: `"name": "mutation"`, `"displayName": "The libraries with Mull's plugin, for scripts/check/mutation.py (clang 21, Linux)"`, `"binaryDir": "${sourceDir}/build-mutation"`, `"environment": { "MULL_CONFIG": "${sourceDir}/scripts/check/mull.yml" }`, and `cacheVariables` `CMAKE_BUILD_TYPE` `Debug`, `CMAKE_C_COMPILER` `clang-21`, `CMAKE_CXX_COMPILER` `clang++-21`, `CMAKE_C_FLAGS` `-O0 -fpass-plugin=/usr/lib/mull-ir-frontend-21 -g -grecord-command-line -fprofile-instr-generate -fcoverage-mapping`, `CMAKE_EXE_LINKER_FLAGS` `-fprofile-instr-generate`, `CF_WITH_CXX` `OFF`, `CF_ENABLE_GATES` `OFF`; and the build preset `{ "name": "mutation", "configurePreset": "mutation", "configuration": "Debug" }` (a build preset takes its configure preset's environment, so the plugin sees `MULL_CONFIG`). No test preset: ctest does not run it. The coverage flags let `mull-runner` skip the mutants a test never reaches.
  * **The driver**: `scripts/check/mutation.py`, Python 3 with the standard library only (as `scripts/check/infer.py`), two subcommands:
    * `run --build <dir> --out <dir> [--shard I/N] [--tests <regex>] [--workers <n>]`: lists the tests with `ctest --test-dir <build> --show-only=json-v1`; keeps those whose name starts with `unit.`, which are not `DISABLED`, have no `WILL_FAIL`, and whose `command[0]` is a file under `<build>` (this drops the must-not-compile tests, whose command is CMake); drops `unit.test_lanes_swar_all` (it fails Mull's warm-up run: 34 s instrumented, every word body of the table kept; `test_lanes` and `fuzz_lanes` cover the same code); with `--tests`, keeps only names the regex finds. Each test is run once without Mull (`LLVM_PROFILE_FILE=/dev/null`, its `WORKING_DIRECTORY` and `ENVIRONMENT` properties, a 300 s limit); one that fails prints `mutation: <name> fails unmutated` and the run exits 2. With `--shard I/N` the tests are dealt out by cost, longest first, each to the shard with the least so far (costs from `scripts/check/mutation-costs.txt`, `<test> <seconds>` a line; a test not in it counts 60 s), and only shard I's are run. Each kept test then runs as `mull-runner-21 --allow-surviving --workers <n> --reporters SQLite --report-dir <out> --report-name <test> --no-test-output --no-mutant-output <command...>` in its working directory, with its environment and `MULL_CONFIG=<source>/scripts/check/mull.yml`; `<n>` defaults to `os.cpu_count()`. A runner exit other than 0 prints `mutation: <name>: mull-runner exit <rc>`, and the run exits 2 after the other tests. One report a test, `<out>/<test>.sqlite` (one runner call writes one report; a shared name would be overwritten by the next test). It writes `<out>/costs.txt`, `<test> <seconds>` for each test run, longest first.
    * `report [--floors <file>] <path>...`: each path is a `.sqlite` file or a directory, whose `*.sqlite` files at any depth are read; reads every report's `mutant` table (`mutant_id`, `filename`, `execution_status`), merges by `mutant_id`, and calls a mutant killed if any report gives it a killed status. Killed are failed, timed out, crashed and an abnormal exit; survived is passed; not covered counts as survived, as Mull counts it (step 2 confirms the codes). The component is `<c>` of `lib/<c>/src` in the file name. It prints a Markdown table, `| Component | Mutants | Killed | Survived | Score |`, a row a component in name order and a last row `all`, the score with one decimal, then up to 20 surviving mutants of the lowest-scoring component as `file:line:col mutator`. With `--floors`, a component (or `all`) whose score is below its floor prints `mutation: <component> <score>% is below its floor <floor>%` and the exit is 1; a component the file does not name has no floor; a line naming a component the reports lack is an error (exit 2), so a floor never stands on nothing.
  * **The floors**: `.mutation-floors.txt` at the root, `<component> <percent>` a line, `#` comments, the percent an integer: the score of the first full CI run of this card rounded down, less one (a test that times out in one run and not the next moves a score by a fraction). They are raised by hand as tests are added, never lowered without a line in the card that lowers them.
  * **verify**: an `EXTRA` step `mutation`, after `eva` in `scripts/verify.cmake` (`elseif(x STREQUAL "eva")`, 740-755), with a line in the header's list, after the `eva` entry (37-38): "mutation Mull's mutants of lib/*/src against the unit tests, each component held above its floor in .mutation-floors.txt (scripts/check/mutation.py); hours, not minutes". Skipped with `mutation              skipped: no mull-runner-21` when `mull-runner-21`, `clang-21` or Python 3 is missing, or on Windows. Its steps: `mutation configure` (`cmake --preset mutation`), `mutation build` (`cmake --build --preset mutation ${parallel}`), `mutation run` (`python3 scripts/check/mutation.py run --build build-mutation --out build-mutation/mutation`, plus `--tests ${MUTATION_TESTS}` when `-DMUTATION_TESTS=<regex>` is given), `mutation report` (`python3 scripts/check/mutation.py report --floors .mutation-floors.txt build-mutation/mutation`, without `--floors` when `MUTATION_TESTS` is given: a partial run is not held to the floors). The report directory is emptied before the run, so a report never mixes two runs. "mutation" is also added to the `unknown EXTRA step` error text (`verify.cmake` 1368-1373, after `eva` in its list), and is NOT added to the release list that appends to `EXTRA` (118-146): a run of hours is asked for, never implied.
  * **CI**: `.github/workflows/mutation.yml`, in the form of `eva.yml`: `permissions: contents: read`; on `schedule` (`'17 4 * * 0'`), `workflow_dispatch`, and `push` to any branch with `paths` `scripts/check/mutation.py`, `scripts/check/mull.yml`, `scripts/check/mutation-costs.txt`, `.mutation-floors.txt`, `.github/workflows/mutation.yml` (a change to the tool runs it, so this card's branch does; a change to the library waits for Sunday). Job `run`: `ubuntu-26.04`, `timeout-minutes: 180`, `strategy: { fail-fast: false, matrix: { shard: [1, 2, 3, 4] } }`; steps: `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7`; `sudo apt-get update && sudo apt-get install -y --no-install-recommends clang-21 ninja-build`; both packages by `curl -fsSL -o "$RUNNER_TEMP/<name>" https://github.com/mull-project/mull/releases/download/0.39.1/<name>`, each followed by its `sha256sum -c` line, then `sudo apt-get install -y --no-install-recommends "$RUNNER_TEMP"/Mull-*.deb`; `cmake --preset mutation`; `cmake --build --preset mutation -j 4`; `python3 scripts/check/mutation.py run --build build-mutation --out mutation-out --shard ${{ matrix.shard }}/4 --workers 4`; `actions/upload-artifact@cf430e030ddbb5b0abf93d22962f4752f3646cd9 # v7` with `name: mutation-${{ matrix.shard }}`, `path: mutation-out`, `if: always()`. Job `report`: `needs: run`, `if: always()`, `ubuntu-26.04`; the checkout; `actions/download-artifact@9000827ccba6bdab643e8b6fd33ac0654aef8333 # v8` (as `bench.yml` pins it), `pattern: mutation-*`, `path: reports`; then `set -o pipefail; python3 scripts/check/mutation.py report --floors .mutation-floors.txt reports | tee -a "$GITHUB_STEP_SUMMARY"`. Not a required check.
  * **Costs**: `scripts/check/mutation-costs.txt` starts from the measured times above (the twelve named) and is replaced by the `costs.txt` of the card's first full local run (step 6).
