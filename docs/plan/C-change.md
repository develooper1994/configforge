# C - for the people who change configuration

This group serves the people who change configuration and want to know, before
a merge or a deploy, what a change does: `configforge diff` that reads the
contract (arrays of arrays, durations and sizes compared as values, the keys
out of range or touching a secret), the durations and sizes a contract can
hold, the pull request's comment that says it, drift across many hosts, and the
help, completions and sample files a contract already has the facts for. Each
card is read cold against the tree, by someone who did not write it, before it
opens (docs/Plan.md, "Read again after the layout changes"); the line numbers
are those of `2395d65`. The Roadmap's item on Git's `textconv` driver has no

## C-1a - `configforge diff` over arrays of arrays

* **id**: C-1a
* **goal**: `configforge diff` compares a named array whose elements are all arrays of scalars element by element: `$["m"][1]` names the inner array 1 of `m`, and a changed, added or removed inner array is one line; mixed, deeper or root arrays stay refused.
* **why**: a matrix of values (`[[1,2],[3]]`, TOML's `[[...]]`-free nested arrays, YAML flow sequences) is refused today (`tools/diff/main.c:98-99`: `begin_array` returns `CF_FALSE` while `array_next` is set), so a pull request that changes one is "could not be compared". Roadmap: "What is left: arrays of arrays".
* **needs**: nothing
* **size**: medium
* **decided**:
  * **Entry kinds.** A fourth kind `ENTRY_ARRAYS` (`main.c:22`, the enum). An array named `a` whose first element is an array is an `ENTRY_ARRAYS` entry at `$["a"]`, as `ENTRY_TABLES` is (`main.c:92-96`). Its elements are entries of their own, kind `ENTRY_ARRAY`, path = the outer path plus an index segment `{NULL, i}` (`main.c:15-20`, `key_order` already sorts an index segment before a name, 242-269), numbered from 0 in the order the reader delivers them. They print as `$["m"][1]`.
  * **Compared as tables are.** `entry_equal` (401-423) returns `CF_TRUE` for two `ENTRY_ARRAYS` (their elements carry the difference); a kind mismatch is `changed` at the outer path (`[1]` against `[[1]]` prints `changed` for `$["m"]` and `added` for `$["m"][0]`, in that order, as the sort gives). An inner array is a value even when empty (`{"m":[[],[1]]}` has two elements; `{"m":[[]]}` against `{"m":[[],[]]}` prints `added` for `$["m"][1]`), as an empty scalar array is (`docs/Tools.md:84-85`).
  * **One level.** An inner array holds scalars only. Refused (input refused, exit 2, as today): an array mixing scalars and arrays (`[[1],2]`, `[1,[2]]`), tables inside an inner array (`[[{"a":1}]]`), an array of arrays of arrays, an array of arrays inside an array of tables' element, a root array. The cap `DIFF_SEGMENTS` (64, `main.c:12`) is unchanged; an inner entry needs `s->tables + 1` segments.
  * **No repeats.** A name that holds an array of arrays and is defined twice in one table is refused, like arrays of tables: `no_repeated_tables` (291-306) tests `ENTRY_ARRAYS` as well as `ENTRY_TABLES`.
  * **State.** `side` (41-56) gains `entry* outer` (the `ENTRY_ARRAYS` entry being filled, NULL otherwise) and `cf_bool in_inner`. `begin_array` (161-178) with `name == NULL` and `s->array != NULL` and `!s->in_element` and `!s->in_inner` is an inner array: on the first one, `a->kind = ENTRY_ARRAYS` is allowed only when `a->value.items == NULL` (no scalar yet; else refuse), later ones only when `a->kind == ENTRY_ARRAYS`; a new `record_indexed(side*, const entry* outer, size_t index)` allocates the entry with `outer->depth + 1` segments, copies `outer->path` and appends `{NULL, index}` (the same arena accounting as `record_entry`, 128-159); `array_next` points at the inner entry's `items`; `in_inner = CF_TRUE`. `scalar` (214-240) already appends to `*array_next`. `end_container` (180-203) first closes an inner array (`in_inner` true: `array_next = NULL`, `in_inner = CF_FALSE`, return true), then the outer as now. A scalar arriving at the outer level of an `ENTRY_ARRAYS` entry (`array_next == NULL` and `a->kind == ENTRY_ARRAYS`) is refused in `scalar`; a table arriving at it is refused in `begin_table`. `read_side` (308-358) refuses a document that ends with `in_inner` set.
  * **Rejected**: arrays of arrays of tables and deeper levels (the maintainer's, with `DIFF_SEGMENTS`); reporting the position of the changed element inside an inner array (an inner array is one value, as `peers` is, `docs/Tools.md:79-82`).

## C-1b - `configforge diff --schema`: units compared as values

* **id**: C-1b
* **goal**: `configforge diff --schema S LEFT RIGHT` reads the contract S (a JSON Schema, D-64) and compares a key the contract gives a unit by its value in that unit, so `"30s"` on one side and `30000` or `"30000ms"` on the other are equal; without `--schema` nothing changes.
* **why**: plain semantic diffs (dyff, graphtage) say `30s` became `30000ms` when nothing changed. Roadmap: "With a contract, units compared as values (`30s` is `30000ms`, with 1.10.0's durations and sizes), which plain semantic diffs do not do."
* **needs**: C-2a and C-2b (the unit on a definition, the parser, the schema keyword), C-1a only for the file's line numbers
* **size**: medium
* **decided**:
  * **The option.** `--schema S` (once, before the paths, as `--as-left` is parsed, `main.c:477-497`); usage becomes `usage: configforge diff [--as-left FORMAT] [--as-right FORMAT] [--schema SCHEMA] [--] LEFT RIGHT` (`main.c:456-460`; the front door's help is this text). A missing or repeated `--schema`'s argument is a usage error (exit 2) as for `--as-left`.
  * **Reading the contract.** As `gen_load` does (`tools/gen/contract.c:2182-2195`): `cf_arena_new(NULL, 0)`, `cf_defset_init(&ds, ar, 0)`, `cf_defset_schema_file(&ds, path, &err)`. A refusal prints `diff: schema refused: <err.message>\n` and exits 2, before either file is read; in a build without the JSON reader the same line carries the library's own message (`schema.c:785-805`).
  * **Which entries.** An entry is looked at when all the segments of its path are names (no index segment, so nothing inside an array of tables or of arrays), none contains a `.`, and the segments joined by `.` are at most `CF_KEY_MAX` bytes: `cf_defset_find(&ds, key, len)` (`cf_define.h:257`) gives its definition. A scalar entry or an array of scalars (a list definition: `list_mode != CF_LIST_NONE`) is normalised; any other entry is compared as now. The tool defines `CF_INTERNAL_API=1` for itself (`tools/diff/CMakeLists.txt`: `target_compile_definitions(configforge_diff PRIVATE CF_INTERNAL_API=1)`), and links `configforge` instead of `configforge_serialize` alone (as `tools/gen/CMakeLists.txt:21` does). The Windows shared-build copy step in `tools/diff/CMakeLists.txt` (`copy_if_different $<TARGET_FILE:configforge_serialize>`) copies `$<TARGET_FILE:configforge>` as well (the tool needs both DLLs beside it).
  * **The rule.** For a definition whose `unit` (C-2a) is not `CF_UNIT_NONE` and whose `type` is `CF_TYPE_INT`: a value of type `CF_TYPE_TEXT` is converted with `cf_unit_value(def->unit, p, n, &out)` (C-2a) and, when that succeeds, replaced by the int `out` before `cf_value_equal`; a text that does not parse stays text and so differs from every int. An int is already in the unit. Applied to each element of a list. Types are otherwise exactly as the readers delivered them: a contract does not make `"8080"` equal `8080`.
  * **Where.** `entry_equal` (401-423) and `compare` (425) gain a parameter `const cf_defset* ds` (NULL without `--schema`; `main` owns the set and passes it down; `side` does not change). The normalisation is made in `entry_equal`, on a copy of each value (`cf_value` is a plain struct, `cf_base.h`), so the stored entry keeps what the reader delivered; no output changes.
  * **No flag in the output yet.** The lines stay `kind TAB path`. C-3a adds the flags.
  * **Decision D-114** (copy into `docs/Decisions.md` as a row of the table at line 127's style and a section after D-112, "## D-114 — `configforge diff` reads the contract"): "Question. Can `configforge diff` know that `30s` and `30000ms` are one value? Decision. Given `--schema S` it reads the contract as `gen check` does and compares a key whose definition has a unit by its value in the unit; a text that is not a duration or a size stays text. Held to. `tests/front/diff.cmake`; no value is printed. Weighed and not taken. Reading units from the files themselves (`ms` is a suffix and a name at once), comparing every typed string with its declared type (a wider change that makes `\"1\"` equal `1`)."
* **files**: `tools/diff/main.c`, `tools/diff/CMakeLists.txt`, `tests/front/diff.cmake`, `tests/front/units.schema.json` (new), then `docs/Tools.md`, `docs/Decisions.md`, `CHANGELOG.md`, `docs/Roadmap.md`, `docs/Codemap.md` and `docs/API.md` (generated).

## C-2a - Durations and sizes: the unit on an int definition

* **id**: C-2a
* **goal**: a definition of type int may carry a unit, `CF_UNIT_MS` or `CF_UNIT_BYTES`; text such as `"1h30m"` or `"512MiB"`, from the command line, the environment, INI, `.properties`, dotenv, or a quoted string in JSON, TOML and YAML, is read as the int in the unit (5400000 and 536870912), within the range given in the unit, and `explain()` shows both the number and the text as written.
* **why**: `"30s"`, `"1h30m"` and `"512MiB"` are the commonest values a configuration holds and here they are text or a bare int (`docs/Roadmap.md:839-846`). The value is typed once, where the contract is applied (`lib/config/src/core/validate.c:237-278`), so every read afterwards is an int.
* **needs**: nothing
* **size**: medium (the parser and the conversion; the schema, the report and `cf_emit` are C-2b)
* **decided**:
  * **TO DECIDE (the maintainer: a new public interface and an ABI field).** What is decided here is the recommended shape: `typedef enum cf_unit { CF_UNIT_NONE = 0, CF_UNIT_MS, CF_UNIT_BYTES } cf_unit;` in `lib/config/include/configforge/cf_define.h` before the comment that opens `cf_def` (line 60; `typedef struct cf_def` is line 68), and one field `cf_unit unit;` appended as the last field of `cf_def` (after `list_default_count`, line 133; the struct closes at 134), so a caller built against 1.8 (`size` smaller) has it zero: `cf_define` (`define.c:395`) copies only `d->size` bytes into a zeroed copy (`define.c:405-418`), and there `#define DEF_SIZE_UNIT (offsetof(cf_def, unit) + sizeof(((cf_def*)0)->unit))` is added beside `DEF_SIZE_LIST` (line 19) with `if (d->size < DEF_SIZE_UNIT) { normalized.unit = CF_UNIT_NONE; }` in the block at 412-417 (D-51). Alternatives: a new `cf_type` (rejected by the Roadmap: the enum is in the ABI, and an int with a unit is still an int to every reader of the value); a separate `cf_def_duration()` constructor only (cannot be set from a schema or by a binding that lays out `cf_def`). Everything below follows the recommendation; the first card step that touches `cf_define.h` waits for the answer under "Organiser's answers".
  * **Parsers** (`lib/numeric`, which depends on `port` only, so no `cf_unit` there; internal tier like `cf_text_to_i64`, `cf_numeric.h:34-37`): `CF_API cf_bool cf_text_to_ms(const char* s, size_t n, cf_i64* out);` and `CF_API cf_bool cf_text_to_bytes(const char* s, size_t n, cf_i64* out);`, both under `#if CF_INTERNAL_API`, implemented in `lib/numeric/src/numeric.c` after `cf_text_to_i64` (which ends at line 96). The dispatcher over the enum lives in config: `CF_API cf_bool cf_unit_value(cf_unit unit, const char* s, size_t n, cf_i64* out);` declared in `cf_define.h` under `#if CF_INTERNAL_API` (as `cf_defset_count` is, 281-282) and defined in `lib/config/src/core/define.c` (it calls the two, and returns false for `CF_UNIT_NONE`).
  * **Grammar.** No whitespace anywhere, no sign on a suffixed form, case-sensitive, base 10, no fraction. A bare integer (optionally signed, what `cf_text_to_i64` takes) is the value in the unit: `"30"` is 30 ms. `CF_UNIT_MS`: one or more terms `digits suffix`, suffix in `ms`, `s`, `m`, `h`, `d` (1, 1000, 60000, 3600000, 86400000 ms), the suffixes strictly decreasing in size left to right (`1h30m` and `2d12h`, not `30m1h`, not `1h1h`); `m` is minutes (`ms` is tried first). `CF_UNIT_BYTES`: one term `digits suffix`, suffix in `B`, `KB`, `MB`, `GB`, `TB` (1000^k) or `KiB`, `MiB`, `GiB`, `TiB` (1024^k); `K`, `M`, `G` alone are refused (they are ambiguous). Each product and sum is checked against `INT64_MAX` (`cf_i64`) before it is made; overflow is a refusal. `CF_UNIT_NONE`: returns false. An empty string, a leading `+`, `1.5h`, `1 h`, `1H`, `10x` are refused.
  * **Conversion** in `apply_candidate` (`validate.c:237-278`): a new static `unit_value(const cf_def*, cf_candidate*, const char** why, ...)` used by two branches: the textual branch (243-263) when `d->type == CF_TYPE_INT && d->unit != CF_UNIT_NONE` calls `cf_unit_value` instead of `cf_value_from_text`; and a new branch before `else if (c->value.type != d->type)` (264) for a typed text (`c->value.type == CF_TYPE_TEXT`, a JSON/TOML/YAML quoted string) of such a key, which is converted the same way (the only coercion a typed source gets, because the contract declared a unit). A refusal: kind `CF_REFUSAL_TYPE`, reason `"<text>" is not a valid duration` (ms) or `... is not a valid size` (bytes), sealed to the kind's fixed wording for a sensitive key, as 250-257 do. On success `c->written` is set to the text as written (`c->value.u.t.p`, arena-owned) when it is NULL, before `c->value = converted`, so `explain` prints `, from "30s"` (`explain.c:113`) and the report prints `"written"` (`report.c:305`) with no change to either. A text that came through references (`${...}`, `validate.c:422`, `544`) goes through the same function after expansion and keeps its template as `written`.
  * **Range and default** are in the unit: `cf_def_int(..., min, max)` (`define.c:560-575`) and `imin`/`imax` are milliseconds or bytes; a text default is not allowed (a default is a value: `has_default` with an int in the unit). `def_check` (175-308) refuses `unit != CF_UNIT_NONE` with `type != CF_TYPE_INT` (`"a unit needs an int"`), a unit value beyond `CF_UNIT_BYTES` (`"unknown unit"`); a list of ints with a unit is allowed (each element converts).
  * **Not done here**: the schema keyword, the report's definition, `cf_emit`, the other readers' tests (C-2b); TOML dates and YAML timestamps (the Roadmap: "if asked for"); C++, Rust and Python typed keys (they take the C definition through the schema); `cf_usage`'s line (a later card may print the unit).
  * **Decision D-113** (copy into `docs/Decisions.md`, a table row at the style of line 127 and a section after D-112, "## D-113 — A unit on an int definition"): "Question. How does a configuration hold `30s` and `512MiB` without a new `cf_type`, which would change the ABI? Decision. `cf_def` gains `unit` (`CF_UNIT_MS`, `CF_UNIT_BYTES`); an int definition with a unit accepts a text of the grammar (`1h30m`, `512MiB`; bare digits are the unit) and keeps the int in milliseconds or bytes; the range is in the unit; the provenance keeps the text as written; a typed source's string is converted for such a key and for no other. Held to. `lib/numeric/tests/test_numeric.c` for the grammar and `lib/config/tests/test_units.c` for the contract. Two choices. `KB` is 1000 and `KiB` is 1024, and a bare `K` is refused rather than guessed; the suffixes of a duration must decrease, so `30m1h` is a mistake and not 90 minutes. Weighed and not taken. A new `cf_type` (ABI), floating-point durations (`1.5h`: rounding), locale-dependent spellings."
* **files**: `lib/numeric/include/configforge/cf_numeric.h`, `lib/numeric/src/numeric.c`, `lib/numeric/tests/test_numeric.c`, `lib/config/include/configforge/cf_define.h`, `lib/config/src/core/define.c`, `lib/config/src/core/validate.c`, `lib/config/tests/test_units.c` (new), `lib/config/tests/CMakeLists.txt` (add `test_units` to the `CF_UNIT_TESTS` list, beside `test_help`, line 36), then `CHANGELOG.md`, `docs/Decisions.md`, `docs/Codemap.md`, `docs/API.md` (generated).
